# ForgePath Cross-Device UX Audit 2026-08-10

## Outcome

ForgePath 0.34.0 passes the release-level mobile and desktop UX audit. Six cross-screen problems were corrected: inherited destination scroll, invalid onboarding landmarks and progress semantics, mobile notices that obstructed the task, delayed Today actions, Library calibration detail appearing before movement discovery, and an active-workout footer that over-emphasized finishing before logging work.

No P0 blocker or data-integrity defect was found. The completed corrections change presentation, navigation context, and interaction hierarchy without changing training calculations, source history, backup schema 24, or local persistence 22.

## Scope and Method

The audit covered:

- onboarding and Quick Start;
- Today and session explanation;
- Plan and mesocycle review;
- Progress across its major analytics surfaces;
- Library search, filters, categories, history calibration, and exercise detail;
- You profile, settings, privacy, and diagnostics;
- active workout warm-up, set logging, substitutions, progress, and finish;
- desktop Chromium and a 390 by 844 phone viewport;
- keyboard focus, landmark semantics, accessible naming, live regions, reduced motion, horizontal containment, console integrity, responsive hierarchy, and production performance.

The review combined direct visual inspection, task walkthroughs, Nielsen heuristic analysis, cognitive-load review, static interface scanning, Lighthouse, deterministic tests, and forty-eight Playwright journeys across desktop and phone.

## Reconciled Product Input

JB's `hypertrophy-app-requirements.md` was reviewed as part of the audit because new programming controls change information architecture and future interaction load. Its mesocycle, exercise-history, upper-lower template, per-exercise increment, and machine-selection ideas are now R-331 through R-340 and Build Bible Chapter 72.

The source's five-to-ten repetition failure loop is intentionally a selectable hypertrophy policy. It is not a universal replacement for ForgePath's load-first general progression, RIR-based prescriptions, readiness gates, protected strength anchors, power work, return-to-training calibration, or pain-aware behavior. This boundary prevents a simple future control from creating unsafe or misleading behavior elsewhere.

## Findings and Corrections

| Priority | Surface | Finding | Correction | Verification |
|---|---|---|---|---|
| P1 | Primary navigation | A destination could inherit a deep scroll position from the previous screen, making Progress or Library appear to open in the middle. | Every navigation change resets document and main-region scroll, then focuses the new main region. | New desktop and phone journey verifies deep Progress scroll followed by Library at scroll position zero. |
| P1 | Today on phone | Header, save state, repeated strategy copy, and a large hero could delay the useful action. | The hero objective now states only the exact anchor and immediate progression. The local-save pill and compact spacing preserve the primary start action in the first 390 by 844 viewport. | Phone viewport assertion and visual review. |
| P1 | Library on phone | Advanced placement-history calibration appeared before search and the category grid consumed several screens. | The movement browser now precedes placement calibration. Compact screens hide redundant descriptive copy, use a three-action row, and present categories as a horizontal strip before visible search and filters. | Phone search-in-viewport assertion, visual review, and full Library journeys. |
| P1 | Active workout | Finish workout used primary lime styling even at 0 of 16 sets, competing with the actual task. | The footer shows completed-set progress and keeps Finish secondary until every planned set is complete. Partial or stopped sessions remain possible. | Desktop and phone class and progress assertions. |
| P1 | Transient notices | Long mobile notices sat above the bottom navigation and could cover the next useful action. | Notices remain dismissible, become ten-second atomic statuses, and move to the compact-screen top. Durable state remains elsewhere. | Mobile visual review and existing notice paths. |
| P2 | Onboarding accessibility | The skip link targeted no main landmark, the page lacked one main region, and a labeled generic step bar used a prohibited ARIA pattern. | The form panel is now `main#main-content`; the four-step bar is a real progressbar with minimum, maximum, current value, and readable value text. | Production Lighthouse accessibility 100 on mobile and desktop. |
| P2 | Workout density on phone | The objective repeated route prose already available in the exercise card and explanation, while warm-up actions were compact. | Repeated objective prose is removed on phones, route and equipment chips remain, and warm-up actions receive 44-pixel targets. | Full-resolution phone workout review. |
| P2 | Rendering efficiency | Workout progress animated layout-changing width. | Progress now uses a horizontal transform with an explicit origin and retains reduced-motion precedence. | Static scan no longer reports layout transition. |

## Desktop Review

Desktop retains the authored, information-rich field-guide character while keeping primary actions obvious. The fixed navigation is stable and consistently labeled. Today balances the prescription and original pixel-world panel. Library now places the browser before calibration evidence. The workout presents status, timing, exercise context, editable sets, substitutions, and completion without requiring mode changes.

Plan, Progress, and You remain intentionally deep expert surfaces. Their density is acceptable on desktop because information is grouped into panels and evidence remains available at the point of use. They should not become default destinations for a user who only wants to train.

## Mobile Review

The phone experience now behaves as a task-focused companion rather than a compressed desktop dashboard:

- Today reaches a valid start action before the first scroll.
- Library exposes search and filters before advanced evidence panels.
- Category cards use a visible horizontal continuation instead of a six-card vertical wall.
- Active workout leads with any required warm-up response, keeps set work next, and de-emphasizes premature completion.
- The bottom navigation remains unobstructed.
- All audited screens remain horizontally contained at 390 pixels.

Total: 37 of 40, strong for the private-alpha scope.

## Cognitive-Load Review

- Single immediate task: pass on onboarding, Today, Library, and active workout after corrections.
- Primary choice visibility: pass. Each core surface has one dominant action or clearly ranked action set.
- Progressive disclosure: pass with a known depth boundary in Progress and You.
- Working-memory burden: pass for workout logging and Library discovery. The seven Progress time ranges are retained because each maps to a distinct requested analysis horizon and remain horizontally contained.
- Information scent: pass. Labels use athlete language rather than implementation terms, with rule versions reserved for evidence and diagnostics.

## Persona Review

| Persona | Result | Remaining consideration |
|---|---|---|
| Experienced powerbuilder with irregular family schedule | Strong | Continue calibrating schedule and route rules from real use. |
| Returning athlete with low current tolerance | Strong | Placement remains explainable and pain-aware, but thresholds need longitudinal validation. |
| Athlete logging quickly on a phone | Strong | Required warm-up or first set becomes the immediate task; optional detail stays below. |
| New user who wants minimal setup | Strong | Quick Start is immediate and explicitly low confidence. |
| Keyboard or screen-reader user | Good | Landmarks, focus, names, progress, and live regions pass; a full manual assistive-technology workout should precede public release. |

## Automated Evidence

- `npm run check`: passed.
- UI boundary scan: passed across sixty-four shipped interface files.
- Deterministic suite: 191 tests across twenty files, all passed.
- Playwright: forty-eight desktop and phone journeys, all passed in 1.6 minutes.
- Production mobile Lighthouse: Performance 98, Accessibility 100, Best Practices 100.
- Production desktop Lighthouse: Performance 100, Accessibility 100, Best Practices 100.
- Browser console and page-error assertions: passed.
- Horizontal containment: passed in all audited journeys.

The static style scan retains two reviewed exceptions. Inter remains the deliberate readable product typeface documented in `DESIGN.md`. The faint grid exists only on the actual Training Field Guide world surface, where it communicates map and measurement context. Neither finding warrants a change in this release.

## Remaining Priorities

1. Run a manual VoiceOver workout and Library task before any public release.
2. Add internal jump navigation to the longest Progress and You surfaces if real use shows repeated deep-scroll friction.
3. Continue splitting large analytics code only if production field performance falls below the current 98 mobile score.
4. Implement R-331 through R-340 as a versioned plan feature with exact-movement progression tests, not as a global rule toggle.
5. Re-run this audit after cloud sync, social features, the original companion system, or a major navigation change.
